# Application appearance

The integrated settings hub links to `/settings/appearance` for the existing palette/brightness controls. Profile, account groups and password use separate sibling routes; the password page reuses current-password verification and revokes all sessions after a successful change. Device privacy and notification-kind choices remain local. Notification visibility filters affect the list without changing server-side read receipts or financial sources.

> **Integrated source update, 2026-11-20:** The approved layout, paired custom colors, DE/EN display and first-render masking are implemented and locally validated. Production remains unchanged; current CI/user acceptance boundaries are in [status.md](status.md) and E6–E8 in [todo.md](todo.md).

Settings offers 23 device-local preview tiles based on 18 adapted color families. Ordinary families retain an independent system/light/dark preference. The six Ayu tiles explicitly select Light, Dark or Mirage, each bordered/unbordered; selecting a tile activates its brightness. The circular header/login button preserves Ayu border choice and switches Light with the last selected Dark/Mirage variant. Existing stored preferences remain valid.

The catalog in apps/web/app/utils/appearance.ts contains 18 adapted families: Haushaltsbuch, VS Code Modern, GitHub, One Dark Pro, Dracula, Nord, Monokai, Solarized, Catppuccin, Tokyo Night, Gruvbox, Night Owl, Material, Ayu, Rosé Pine, Cobalt2, SynthWave '84 and high contrast. These are app palettes inspired by editor themes, not installed VS Code extensions. Paired light variants are adapted when necessary; they are not advertised as original editor variants.

Primary references: [VS Code theme documentation](https://code.visualstudio.com/docs/configure/themes), [default theme source](https://github.com/microsoft/vscode/tree/main/extensions/theme-defaults), [Dracula specification](https://draculatheme.com/spec), [Nord palettes](https://www.nordtheme.com/docs/colors-and-palettes/) and [Catppuccin palette](https://catppuccin.com/palette/). Individual app tones are selected for readable controls and financial displays rather than syntax-highlighting fidelity. No third-party extension is downloaded or executed by the app.

Nuxt emits static semantic-token CSS into the page head. The early script validates bundled IDs and optionally restores a validated light/dark custom pair from the versioned device workspace preferences before application modules execute. Invalid/missing/blocked storage falls back to default. A client plugin connects Settings to that preference. Nuxt's existing haushaltsbuch-theme key continues to own brightness. Neither preference contains bank, session or financial data.

`/settings/appearance/custom` edits six opaque hexadecimal colors per mode: canvas, surface, primary text, secondary text, accent and accent text. Both modes must pass the semantic background checks before replacing the working pair: at least 4.5:1 for normal text and 3:1 for essential control/chart boundaries. Fixed financial meaning colors remain independently validated. Rejected drafts retain the working theme and focus the invalid field; choosing a bundled family retains the saved pair. Storage failures keep the session usable without replacing the previous durable family with an unpersisted custom identity. The editor reset only resets its draft.

Tests measure foreground/secondary/action/button/financial text contrast for both modes of every family, execute the real bootstrap with allowed/invalid/blocked storage and exercise the actual browser controls, reload, logout, keyboard and reduced motion. Integrated acceptance additionally checks layout, modal focus, loading/empty/error recovery, long DE/EN labels and large exact amounts across nine widths. Normal/reduced-motion recordings at 390/768/1440 px verify restrained 180 ms opacity feedback and stationary tiles. These checks are recorded in [feature validation](../specs/001-integrated-household-concept/validation.md); static palette ratios alone are not full accessibility proof.

The approved reference retains 17/32 px narrow/wide gutters, 22 px tile radii and distinct section/inner spacing rather than forcing every surface to one density. Colors remain semantic across canvas, surface, selected controls and inert dialog backdrops. Theme families retain their identity; synthetic prototype financial values are not copied into the real interface.

Language, amount masking, selected modules/chart style, notification-kind filters and custom pairs use versioned device preferences. DE/EN formatting preserves exact decimal-string money and Berlin calendar dates; source account/category/merchant/contract names remain untouched. Masking replaces rendered financial text and accessible chart information instead of merely covering visible characters. It is a presentation setting, not authentication. Blocked/quota-limited storage keeps current choices in memory with a notice; reload restores the last durable choices. Neither profile/group metadata nor password/session state is stored as an appearance preference.
