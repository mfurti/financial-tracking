# Data Model: Rebuild the Household Ledger

The current Prisma schema and ordered SQL migrations define persisted records. Phase 1 designs a read model and cutover around those records. A schema change would require specific migration design and compatibility evidence.

| Entity                                      | Preserved fields and relationships                                                                                                                             | Validation or transition rules                                                                                                                                                 |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Accounts, balance snapshots, account groups | Stable account IDs, currency, source/type, presentation, observation amount/date, group membership                                                             | Report unknown balances and observation coverage explicitly. Preserve included versus hidden scope and distinguish observed balances from booked movement.                     |
| Transactions and source identities          | Stable transaction ID, optional account, source and import provenance, booked date, signed amount in cents, category, transfer membership, and source identity | Preserve accountless CSV rows, deduplication, assignment and rollback rules. Keep current transfer exclusion and signed amount semantics.                                      |
| Categories and rules                        | Stable category and rule IDs, matching and precedence, classifications and dependencies                                                                        | Use validated domain commands for reclassification. Active and archived categories retain their established meanings.                                                          |
| Imports and bank connections                | Run, issue, staged row, assignment receipt, transaction links, secure connection configuration                                                                 | Preserve preview/commit, duplicate handling, synchronization authorization and eligible rollback. Keep bank secrets and pending authorization internals outside table outputs. |
| Contracts, revisions and payments           | Contract details, due dates, recurrence/direction, revision history, suggestions and payments linked to transactions                                           | Distinguish estimates and due dates from recorded payments. Update relationship and history through the existing transactional commands.                                       |
| Reserve and recorded wealth                 | Goal configuration, immutable wealth records and components, frozen observation labels, reporting dates and coverage                                           | Preserve retry behavior for capture. Preserve missing versus zero and exact component totals.                                                                                  |
| Access and workspace                        | User, session, owner profile, scoped account settings and notification acknowledgements                                                                        | Preserve authentication, session expiry, CSRF and permission checks. ## Read Models

- Transaction rows retain stable IDs, booked date, signed amount as a decimal string representing integer cents, currency, allowed description or counterparty, and approved account/category summaries. Absent accounts and categories retain the established null handling.
- Account and contract rows use their own public field definitions. Related data is returned only when explicitly mapped and selected.
- Table page state consists of the current page, bounded page size, filter/facet values, sorting, and total counts. It is derived per request. User-authorized scope precedes both count and row selection.
- Periods retain current ledger date semantics. Dates without a time of day remain date-only. Calculations use integer cents across the system and convert to strings at the wire boundary.

## Cutover Evidence

Use a recent synthetic or anonymized restore preserving relationships. Compare migrations, record counts, IDs, key joins and reconciled totals by account, month, and currency. Compare accountless and linked-transfer cases separately. Include import receipts, contract links, immutable wealth components, configuration and access checks. Verify that both deployed-generation code and the rebuild can use the unchanged schema during transition. Reconcile the data baseline again if a pending change adds budgets or transaction splits before implementation.
